## 1 · Does adding and editing a place work `[x]`

Yes — and there was one real fault under it, which is why the answer took a
walk through the data rather than a click through the form.

- [x] **Two places carry the Board's own dashboard edits** — `gurudwara-dasvin`
      and `kali-kamli` are unhidden in the database and hidden in the bundled
      copy. Somebody edited them here, and it saved. That is the proof
- [x] **The form draws every one of a place's 30 fields**, reads them back
      through one selector, and saves through `PUT /admin/content/places` —
      `check-forms.mjs` renders every kind with every field populated
- [x] **Empty is stored as absent, not as ""** — which is why the same two
      places came back without `placeId`, `closed` and an empty `gallery`.
      Normalisation, not loss

  ↳ **A key no field owns is DROPPED on save, silently.** `readGroup` builds
  the saved document from SPEC alone, so `hoursEst` (on 19 places) and
  `approx` (on 11) would have been deleted by one edit each — the caveat
  gone, the guess left reading as a fact. Both are checkboxes in the form now.
  ↳ **`breaks` on `p-saraswati-van` was read by nothing at all** — no field, no
  renderer, no rule. Removed, here and in the database.
  ↳ **New check 8f in `check-forms.mjs`**: every key the catalogues carry must
  be a key some field owns. This class of fault cannot come back quietly.

## 4 · The one that is red `[ ]`

`check-planner` fails: a six-stop walking pocket from Sannihit Sarovar covers
1148 m where 843 m was available — Nabha House → Panorama → Krishna Museum →
Kali Kamli → Gurudwara Chhevin → Laxmi Narayan. 36% over, against a 5% bar.

**Production has been doing this for weeks.** The database unhid Kali Kamli
when the Board edited it; only the bundled copy still said `pending`, so the
check was measuring a day that no visitor was being given. Syncing the two is
what made it visible. That is the check working, not the check breaking.

Not fixed today, and not by a knob: the pocket's order comes from a value
score, and sweeping the walk-distance weight from 0.8 to 2.2 changed neither
the order nor the metres. The real answer is a 2-opt pass over the pocket's
walking legs with the opening hours re-checked — the same thing `twoOpt.ts`
does for the driving leg — and it changes every itinerary the app builds, so it
wants its own session and the whole suite as the judge.

## 5 · A cache in front of the Worker, and pictures that arrive sooner `[x]`

- [x] **Workers Cache is on** — `[cache] enabled = true`, four lines in
      `wrangler.toml`. A hit is answered at the edge **without running the
      Worker at all**: no CPU, no Neon query, no R2 read. Verified live:
      `cf-cache-status: MISS` then `HIT` on both a feed and a photograph
- [x] **It works on workers.dev**, which the older Cache API does not — no
      custom domain needed to get the win, and no separate bill: hits cost a
      request and nothing else
- [x] **Feeds: `max-age=60, s-maxage=60, stale-while-revalidate=600`** with a
      `Cache-Tag` per kind, purged on every dashboard write
- [x] **Photographs: a day in the browser, an hour at the edge**, tagged per
      key so replacing one picture does not evict the other ninety-eight
- [x] **The app stopped forcing a revalidation** — `live.ts` used to fetch six
      feeds with `cache: "no-cache"` on every launch, which is six database
      reads to be told six times that nothing had changed. The bundled copy is
      already on screen and the IndexedDB copy is already applied; this call
      was never the one anybody was waiting for
- [x] **`preconnect` to the media origin** — the app is on Pages and the
      pictures are on workers.dev, so the first photograph used to pay a DNS
      lookup, a handshake and a TLS negotiation before a byte moved
- [x] **`decoding="async"` on all 18 image tags**, app and dashboard
- [x] **`fetchPriority="high"` on the two heroes** — the home carousel's first
      slide and a place's first photograph are the largest thing on their
      screen, and were queueing behind thirty tiles the browser could not know
      were below the fold
- [x] **`content-visibility:auto` on the library tiles** — `loading="lazy"`
      stops the fetch; this stops the decode and the paint of a hundred
      full-size photographs drawn into 76-pixel boxes

  ↳ **The dangerous default, caught before it shipped.** Workers Cache treats a
  200 with NO cache-control as cacheable for two hours, so silence is opting
  IN. `json()` now answers `no-store` unless a route says otherwise, and only
  four routes say otherwise. Verified: `/admin/*` and `/api/auth/*` come back
  `cf-cache-status: BYPASS`.
  ↳ **`npm run import` goes round the Worker**, so it cannot purge. Its writes
  are up to a minute stale at the edge. Noted in the script itself.
  ↳ **Not done: the bundle.** 825 KB, 270 KB gzipped, and Leaflet is in it on
  every screen including the ones with no map. Splitting the map routes out is
  the next real win and it is a bigger change than any of the above.
